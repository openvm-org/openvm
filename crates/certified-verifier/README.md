# openvm-certified-verifier: vendored Lean Swirl verifier

> The contents of this crate are vendored from the private `swirl-rbr-fv`
> repo. That repo is the source of truth: do not edit in place without
> upstreaming the change, and refresh the vendored copy (see below) when it
> moves.

This crate lets `openvm-sdk` (behind its `certified-verifier` feature) run
the certified Swirl verifier extracted from its Lean formalization against
proofs produced by this workspace, as a differential check on the Rust verifier.

## Contents

`csrc/` contains the exact generated-C link closures of `swirl_verify`
and the `swirl_dump_proof` parser test utility. They were generated by
Lean toolchain `leanprover/lean4:v4.26.0`.

There are no prebuilt binaries: this crate's `build.rs` compiles these
sources with `leanc` during the Rust build and links the verifier and Lean
runtime directly into the Rust target. A small OpenVM-owned C adapter uses
`lean.h` to construct `ByteArray`s and inspect the verifier result, exposing
one raw-buffer verification function to Rust. The generated C and adapter are
ABI-coupled to the Lean runtime, so `leanc` from the matching toolchain is
required:

```sh
# one-time setup
curl -sSf https://elan.lean-lang.org/elan-init.sh | sh
elan toolchain install leanprover/lean4:v4.26.0

cargo build -p openvm-certified-verifier
# or, through the SDK:
cargo build -p openvm-sdk --features certified-verifier
```

The build always invokes `leanc` through the pinned elan toolchain. Compiler
overrides are intentionally unsupported. `swirl_dump_proof` is still compiled
as a test-only wire-format utility; proof verification does not spawn it or
any other executable.

## Regenerating csrc/

From a checkout of `swirl-rbr-fv` (requires elan/Lake):

```sh
lake build swirl_verify
lake build swirl_dump_proof
# C closure: the *.c files listed (as .c.o.export) in
#            .lake/build/bin/{swirl_verify,swirl_dump_proof}.trace
```

## Version coupling

The wire format is a hand-written contract between the encoder and
tests in `crates/certified-verifier/` and the Lean decoders
(`swirl-rbr-fv:Swirl/Protocol/Noninteractive/Wire/`). Validated at:

- `swirl-rbr-fv`
- `openvm-org/stark-backend` tag `v2.0.0` (`16d60de`); this workspace's
  pin `fcaff50` was diff-checked equivalent on the `Proof`/vk type
  surface.

If either side moves (Lean structs, wire version, stark-backend proof
shape, the Lean toolchain, or the exit-code table in
`swirl-rbr-fv:Tools/SwirlVerifyMain.lean`), the encoder and the vendored
C sources and vendored tests must be refreshed together.
