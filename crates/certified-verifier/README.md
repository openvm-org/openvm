# openvm-certified-verifier: vendored Lean certified verifiers

> This crate's `csrc` is vendored from the [`openvm-fv`](https://github.com/axiom-crypto/openvm-fv)
> repo. That repo is the source of truth: do not edit in place without upstreaming
> the change, and refresh the vendored copy (see below) when it moves.

This crate lets `openvm-sdk` (behind its `certified-verifier` feature) run the
certified VM verifier extracted from its Lean formalization. It verifies both
the final recursive STARK and the host-side VM public-value conditions.

## Contents

`csrc/` contains the exact generated-C link closure of `vm_verify` and the
`vm_dump_proof` parser test utility. They were generated by Lean toolchain
`leanprover/lean4:v4.34.0`. The VM verifier adds only its
lightweight Batteries, Recursion-layout, and `VmVerifier` modules; its proof
modules and Mathlib are not part of the C closure.

There are no prebuilt binaries: this crate's `build.rs` compiles these
sources with `leanc` during the Rust build and links the verifier and Lean
runtime directly into the Rust target. A small OpenVM-owned C adapter uses
`lean.h` to construct `ByteArray`s and inspect the verifier result, exposing
one raw-buffer verification function to Rust. The generated C and adapter are
ABI-coupled to the Lean runtime, so `leanc` from the matching toolchain is
required:

```sh
# one-time setup
curl -sSf https://elan.lean-lang.org/elan-init.sh | sh
elan toolchain install leanprover/lean4:v4.34.0

cargo build -p openvm-certified-verifier
# or, through the SDK:
cargo build -p openvm-sdk --features certified-verifier
```

The build always invokes `leanc` through the pinned elan toolchain. Compiler
overrides are intentionally unsupported. `vm_dump_proof` is compiled
as a test-only wire-format utility; proof verification does not spawn it or
any other executable.

## Regenerating csrc/

From a checkout of `openvm-fv` (requires elan/Lake):

```sh
lake build vm_verify vm_dump_proof
```

Copy the `*.c` sources listed as `*.c.o.export` in the nested `inputs` of the two traces:

- `.lake/build/bin/vm_verify.trace`
- `.lake/build/bin/vm_dump_proof.trace`

The consistency check resolves the object paths recorded in those traces, including sources built
from `openvm-fv`'s pinned dependencies.

## Version coupling

The wire format is a hand-written contract between the encoder and tests in
`crates/certified-verifier/` and the Lean decoders in the pinned `openvm-fv` revision. Validated at:

- `openvm-fv` tag `v1.0.0-rc.1`
- `openvm-org/stark-backend` tag `v2.0.1`

If either side moves (Lean structs, wire version, stark-backend proof
shape, the Lean toolchain, or the verifier error mapping in `openvm-fv`),
the encoder and the vendored C sources and vendored tests must be refreshed together.

## Testing standard examples

[`test_standard_examples.sh`](./test_standard_examples.sh) reuses one standard key set to prove all
compatible examples and verify their proofs with the certified verifier (`algebra` is excluded
because it uses custom moduli):

```sh
./crates/certified-verifier/test_standard_examples.sh
```
